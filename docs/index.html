Rust / OpenZFS / MIT

ZFS snapshots. Fast, parallel, careful.

zsnap is a policy-driven snapshot manager built as one self-contained Rust binary. It works across zpools in parallel, keeps commands within each pool ordered, and only prunes snapshots carrying its ownership marker.

01 / Design

Less runtime. More control.

Useful Sanoid-style lifecycle policies, rebuilt around strict configuration, one inventory scan, bounded commands, and a small operational footprint.

[01]

Pool-level parallelism

Independent zpools run concurrently. Work inside each pool stays ordered by default, avoiding pointless contention on the same vdevs.

[02]

Conservative pruning

Only snapshots with org.zsnap:managed=yes are eligible. Holds, clones, datasets, volumes, bookmarks, and checkpoints stay outside the destroy path.

[03]

Readable policy

Strict TOML supports templates, concise dataset headers, recursive policies, hooks, host-local time, and explicit UTC scheduling.

[04]

Useful operations

Preview with plan, lint with check, inspect cached status, migrate Sanoid configuration, and notify Discord, Slack, or Flock.

02 / Guardrails

Fast does not mean reckless.

zsnap builds the complete plan in memory before execution and validates every destructive target again at the command boundary.

  • plan and dry runs never mutate ZFS or execute hooks.
  • A failed snapshot or hook stops pruning for that pool.
  • User-held and clone-dependent snapshots are automatically protected.
  • A process-wide lock prevents scheduled and manual runs from overlapping.
root@storage:~ 
$ sudo zsnap check --probe
configuration is valid
ZFS dataset probe succeeded

$ sudo zsnap plan
plan: create 3 snapshot(s),
      prune 1 snapshot(s),
      2 pool(s)

# inspect first, mutate second
$ sudo zsnap run -v
[tank] starting pool work
[backup] starting pool work

03 / Get started

Install it. Name your datasets. Preview.

Releases include static archives plus Debian, RPM, Alpine, and Arch packages for x86-64 and ARM64. Native packages activate a 15-minute schedule automatically.

package install v0.1.0 
# Debian / Ubuntu
$ sudo apt install ./zsnap_0.1.0_amd64.deb

# Fedora / RHEL / CentOS / Rocky
$ sudo dnf install ./zsnap-0.1.0-1.x86_64.rpm

# then configure and preview
$ sudoedit /etc/zsnap/zsnap.toml
$ sudo zsnap check --probe
$ sudo zsnap plan

Start safely: the installed starter selects no pool or dataset. Add exact names from your host, then check and review the plan before the first successful scheduled run.
